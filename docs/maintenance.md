# 保守方針

## 確認する時期

- Renovate の開発ツール更新 PR ごとに、更新に関係する Swift の書き方・非推奨 API・設定を確認し、必要な修正を小さく取り込む。
- Xcode 更新時は、ビルド・lint・ユニットテストに加え、新しい Swift の書き方へ置き換えられる箇所を確認する。
- macOS の新しい安定版が出たら、更新した実機で確認する。

## 更新の進め方

- Swift コンパイラと SDK は Xcode に付属するものを使い、Xcode 自体の更新は Renovate と別に行う。
- 旧環境のためだけの互換処理は追加しない。
- mise 本体と管理ツールの更新は [mise の更新方針](<decisions/mise 本体は固定せず既存の運用に揃える.md>)に従う。

## macOS 更新時の確認

- 最初に、新しい OS 上で既存の配布済みアプリを動かす。
- 次に、採用する Xcode・SDK でビルドしたアプリを同じ OS 上で動かす。
- 両方をシステム設定から選び、実際のスクリーンセーバーホストで確認する。操作方法は [動作確認](../AGENTS.md#動作確認)に従う。

| 確認対象 | 確認すること |
| --- | --- |
| 再生 | 表示・ループ再生・開始と停止 |
| 設定 | 設定シートの表示・保存・閉じる操作、次回起動への反映 |
| 復帰 | スリープからの復帰後に再生できること |
| 複数画面 | 環境がある場合、各画面で再生できること |
| アプリアイコン | 切り替えと、アプリ終了後の保持 |

private API の存在・型を確認するテストや Canvas の成功だけで、実際のホストでの動作確認済みとはしない。

## 記録とリリース

- 確認結果は対象 PR に記録する。コード変更がない場合は確認用の Issue に残す。
- 対象アプリのバージョンまたは commit、macOS の版、ビルドに使った Xcode・Swift の版を記録する。
- 既存配布物と再ビルドしたアプリの結果を分け、成功・失敗・未確認を明記する。
- 変更が必要なら検証後にリリースする。変更が不要なら確認結果を記録し、リリースを必須にしない。
- 現在の互換性を壊す変更、対応 OS の下限引き上げ、既存の保存データと互換性のない変更は major とする。それ以外の保守によるアプリ更新は minor とする。
- 保守によるアプリ更新は main に残るコミット本文の [Release-As](https://github.com/googleapis/release-please#how-do-i-change-the-version-number) に次の番号を明記し、生成されたリリース PR の番号を確認する。
- 配布物のビルドと公開は [リリースフロー](release.md)に従う。
