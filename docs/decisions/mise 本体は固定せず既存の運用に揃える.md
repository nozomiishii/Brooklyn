# mise 本体は固定せず既存の運用に揃える

## 背景と課題

mise への移行にあたり、本体をプロジェクトごとに固定するか、dotfiles のローカル・CI 運用に揃えるかを検討した。

## 検討した選択肢

- 本体を固定する：ローカルと CI の版を揃えられるが、固定版を呼び出す仕組みと更新処理が必要になる。
- 本体を固定しない：更新タイミングの差を受け入れ、既存の運用と揃える。

## 決定

本体の更新を止めない[開発者の方針](https://github.com/jdx/mise/discussions/9864)を採用する。

- mise 本体は固定しない。ローカルはグローバル設定の自動更新を使い、CI は mise-action の既定動作に任せる。
- 管理するツールの版は固定する。
- `min_version` は、新しい mise の機能が必要になった場合だけ追加する。

## 結果

### 良くなったこと

本体を固定するための専用スクリプトと版指定を保守せずに済む。

### 引き受けたコスト

メンバーと CI の更新タイミングがずれる。

### 保留した論点

なし。
